# 任務取消與中斷設計

## Context

TimeScheduler 目前任務一旦加入就無法取消。為了支援取消，需要：
- 追蹤任務狀態（pending, running, cancelled）
- 提供取消 API
- 處理執行緒安全的中斷邏輯

## Goals / Non-Goals

**Goals:**
- 允許取消排程但未執行的任務
- 支援中斷正在執行的任務
- 提供取消回呼通知
- 保持執行緒安全

**Non-Goals:**
- 強制終止執行緒（使用合作式取消）
- 取消歷史記錄或統計
- 複雜的取消條件邏輯

## Decisions

### 取消機制
使用執行緒事件（threading.Event）來實現合作式取消：
- 任務函式需要檢查取消狀態
- 理由：安全，避免強制終止導致資源洩漏
- 替代方案：強制終止被否決，因安全性問題

### 任務狀態
新增狀態枚舉：pending, running, cancelled, completed
- 理由：清晰表達任務生命週期
- 預設狀態：pending

### 取消 API
`Scheduler.cancel_task(task_id)` 返回布林值表示成功與否
- 理由：簡單直觀
- 對於正在執行的任務，設定取消旗標但不立即停止

## Risks / Trade-offs

- **合作式取消依賴**：任務函式必須檢查取消狀態 → 無法取消不合作的任務函式。緩解：文檔說明最佳實踐。
- **執行緒安全**：多執行緒環境下的狀態同步 → 使用鎖保護。
- **API 複雜度**：增加狀態管理使代碼更複雜 → 通過單元測試確保正確性。
